# AZ-104 原廠考試方式 × 練習方式 — TDD 規格

這份文件用測試驅動開發（TDD）的寫法，把兩件事變成**可以逐條驗收的測項**：

1. **原廠考試怎麼考** → 練習頁 `az104-practice.html` 是否忠實重現（機器可測）
2. **要怎麼練才會過** → 你本人是否達到報名的門檻（自己可測）

與 [AZ104-SPEC.md](AZ104-SPEC.md) 的分工：SPEC 講**題庫怎麼做**，本文件講**考試怎麼考、
練到什麼程度才算完成**。兩份都要看。

TDD 的框架、五種錯的分類法、測試金字塔這些**方法論全部沿用 AZ-900**，
見 [AZ900-EXAM-TDD.md](../AZ900/AZ900-EXAM-TDD.md) §0、§3-1、§3-2。
這裡只寫 **AZ-104 的規格**與 **AZ-104 專屬的門檻**。

第 1 節的規格全部在 **2026-07-30 查證過官方頁面**，來源列在第 8 節。

**標記法**：🟢 已通過／🔴 已知不通過／⚪ 尚未實作或尚未驗證；
`[官]` 2026-07-30 查證官方頁面／`[親]` 考後親身回饋／`[社]` 社群回報／`[待確]` 尚未證實。

## 1. 原廠考試方式（規格）

### 1-1 基本參數

**AZ-104 是 role-based（associate）考試，好幾條規則跟 AZ-900 剛好相反**——
下表的粗體就是與 AZ-900 不同的地方。

| 項目 | 規格 | vs AZ-900 | 來源 |
|---|---|---|---|
| 考試代號 | AZ-104 · Microsoft Azure Administrator（**Intermediate 等級**） | 不同 | `[官]` |
| **作答時間** | **100 分鐘** | 45 → 100 | `[官]` |
| **座位時間** | **120 分鐘** | 65 → 120 | `[官]` |
| 題數 | 官方只說「多數考試 **40–60 題**，會變動」；AZ-104 沒有官方數字 | 同 | `[官]` |
| **通過分數** | **700 / 1000** 換算分數（scaled score），官方明講「可能不等於 70% 的分數」 | 同 | `[官]` |
| 計分方式 | **多部分題逐格給分**（可得全部、部分或零分） | 同 | `[官]` |
| 猜題 | **不倒扣**，答錯只是沒分 | 同 | `[官]` |
| 未計分題 | 卷中**混有不計分的試驗題**，不會告訴你是哪幾題 | 同 | `[官]` |
| **開書查 Microsoft Learn** | **可以！** role-based 考試可在作答中開 Learn 分割畫面 | **相反** | `[官]` |
| **Lab（實作題）** | 官方**不公布**哪些考試有 lab。AZ-104 標示 100 分鐘＝官方分類的**「不含 lab」**那一檔（含 lab 的是 120/140 分鐘）。仍以報名時與開場說明為準 | AZ-900 明確無 lab | `[官]` |
| **Case study（案例研究）** | 官方休息規則明文提到 case study，代表 role-based 考試可能出現 | AZ-900 沒有 | `[官]` |
| 語言 | 英文、簡中、**繁中**、韓、日、法、西、德、葡(巴)、義 | 少了印尼／阿拉伯／俄 | `[官]` |

| **認證效期** | **12 個月**，到期前可在 Learn 上**免費線上評量續證** | AZ-900 不過期 | `[官]` |
| 重考 | 第 1 次未過等 **24 小時**；之後每次等待時間不同，見官方重考政策 | 同 | `[官]` |
| 費用 | 依考試所在國家／地區定價 | 同 | `[官]` |
| 報名帳號 | **強烈建議用個人 MSA 帳號**，用公司／學校帳號離職後紀錄會不可回復地消失 | 同 | `[官]` |

### 1-3 題型與本專案的對應

官方**刻意不預告**題型。sandbox 可以玩到：多選、拖放、Hot area、Build list、
Active screen、Case study、Lab、Mark review、Review screen。

| 原廠題型 | 本專案 `k` | 作答方式 |
|---|---|---|
| 單選 | `mc` | 點一個選項 |
| 複選（Each correct answer presents part of the solution） | `mc` | **要剛好選滿 N 項** |
| Yes / No 單句（problem-solution 題組） | `mc` | 兩個選項，順序不洗 |
| Hot area 多句 Yes/No | `hs` | 逐句各自選是／否 |
| 拖放配對 Drag and drop | `dd` | 把項目拖進答案區 |
| Hot area 下拉 | `dl` | 句子裡的下拉選單 |
| Build list 排序 | `dd` + `fix` | 答案區順序本身就是題意 |
| **Case study** | ⚪ **未支援** | 見 §6-3、[AZ104-SPEC.md §5-4](AZ104-SPEC.md) |
| **Lab（實作題）** | ⚪ **不打算做** | 見 §6-4 |
| Active screen（模擬設定畫面） | ⚪ 未模擬 | 沿用 AZ-900 的判斷，不做 |

### 1-4 作答介面的硬規則

沿用 AZ-900 考後回饋（`[親]`，2026-07-28），這些規則 role-based 考試同樣適用：

1. **複選題選滿 N 項才能往下一題**，選滿之後**不吃第 N+1 項**。
2. **拖放就是真的拖放**，下拉就是下拉，多句是非要逐句點。
3. 可以 **Mark for review**，並在 **Review screen** 一次看完哪些沒作答、哪些標了。
4. 可以自由回頭改答案——**但休息與 case study 之後不行**，見下一條。
5. 不倒扣，**交卷前不能留白**。

### 1-5 休息時間的陷阱 `[官]`

- 100 分鐘裡**已經內含 5 分鐘的休息額度**（微軟為此拿掉了一些題目）。
- **考試時鐘不會停。** 休息多久都算你的作答時間。
- **休息之後不能回到休息前看過的任何題目**——即使沒作答、即使標了待複習。
- **lab 進行中、problem-solution 題組中途不能休息**；case study **可以**在中途休息，
  但一樣回不去休息前看過的題目。

→ AZ-104 有 100 分鐘，比 AZ-900 寬裕，但**代價是回不去**。
真的要休息就在「確定不會再回頭的段落之後」休息。

### 1-6 開 Microsoft Learn 的正確用法 `[官]`

這是 AZ-104 相對 AZ-900 最大的差異，但**不是救命稻草**：

- 可存取 `learn.microsoft.com` 全站，**除了** Q&A、Practice Assessments、個人檔案（不能登入）。
- **沒有加時間**，時鐘照跑。官方原文直說：每題都查就做不完，**這是刻意設計的**。
- 分割畫面顯示，可拉寬、可全螢幕、可開多個分頁，可用 Ctrl+F 在**當前頁**內搜尋。
- 連到 Learn 網域以外的連結會被擋。

→ **練習時就要練這件事**：查一題的成本大約是 2–3 分鐘。100 分鐘 50 題平均每題 2 分鐘，
所以整場**最多只查得起 5–8 題**。要事先想好「哪類題目值得查」
（例：具體的角色權限清單、備援選項的名稱細節、某個服務的限制數字），
而不是考場上臨時決定。

### 1-7 常見誤解

| 誤解 | 事實 `[官]` |
|---|---|
| 答對 70% 就過 | 是 **700/1000 換算分數**，官方明講「可能不等於 70% 的分數」 |
| AZ-104 也不能查 Learn | **可以查**，role-based 考試的待遇；但沒加時間 |
| 可以查 Learn 就不用背 | 每題都查一定做不完，官方明講這是刻意設計 |
| 不確定就留白比較安全 | **不倒扣**，留白 100% 拿不到分 |
| 多格題答錯一格整題就沒分 | 原廠**逐格給分**（本練習頁刻意從嚴，見 §6-2） |
| 考過就一勞永逸 | role-based **12 個月到期**，要在 Learn 上免費續證 |
| 遇到超綱怪題 = 準備不足 | 可能是**不計分的試驗題**，官方確認卷中有 |

## 3. 五個領域的配分與時間分配

| 領域 | 分頁 | 官方權重 | 建議時間 | 特性與最容易失分的地方 |
|---|---|---|---|---|
| 身分與治理 | `1` | **20–25%** | 22% | Entra 使用者群組、內建角色與**指派範圍**、Policy／資源鎖／標記、管理群組。**RBAC 角色與 Entra 角色最容易混**，「標記不會被子資源繼承」是經典坑 |
| 儲存體 | `2` | 15–20% | 18% | 備援六種（LRS/ZRS/GRS/RA-GRS/GZRS/RA-GZRS）、存取層、SAS 與預存存取原則、生命週期管理。**名字很像、差別在細節**，最適合用「整組列出」的解析 |
| 運算資源 | `3` | **20–25%** | **25%** | VM、磁碟、可用性區域 vs 可用性設定組、擴展集、ARM/Bicep、容器、App Service。**題量最大，而且會出現程式碼判讀題** |
| 虛擬網路 | `4` | 15–20% | 20% | VNet／子網路／對等互連、UDR、NSG **有效規則**、服務端點 vs 私人端點、負載平衡器。**NSG 有效規則的計算是最常見的情境題** |
| 監控與維護 | `5` | 10–15% | 15% | Monitor 計量與記錄、警示規則與動作群組、Network Watcher、Backup 與 Site Recovery。**權重最低但題目最好拿分**，別放掉 |

比例的依據：權重區間的中位數，再把「運算」與「網路」往上調一點——
這兩塊是 AZ-104 的實作核心，情境題最多、單題耗時最長。

## 4. 測試金字塔

方法論同 [AZ900-EXAM-TDD.md §4](../AZ900/AZ900-EXAM-TDD.md)，只有數字換成 AZ-104 的：

| 層 | 對應 | 怎麼跑 | 頻率 | 通過門檻 |
|---|---|---|---|---|
| **L1 單元** | 單一知識點 | 分頁 `1`–`5` 挑一個領域小量作答 | 每天 | 當下能講出為什麼 |
| **L2 整合** | 一個領域整體 | 分頁 `1`–`5` 各跑完整一輪 | 每 2–3 天 | 該領域 ≥ 80% |
| **L3 端對端** | 整場考試 | **模擬考模式**：50 題 / 100 分鐘 / 不看解析 / 不中斷 | 每週 1–2 次 | ≥ 85%，且 80 分鐘內做完 |
| **L4 回歸** | 修好的不能再壞 | 分頁 `6` 錯題本 + 分頁 `7` 星號題 | 每次 L2/L3 之後 | 同一題**連續兩次答對**才算修好 |

**AZ-104 的 L3 有一件 AZ-900 沒有的功課：練查 Learn 的節奏。**
100 分鐘 50 題＝每題平均 **2 分鐘**（而且含 5 分鐘休息額度）。
模擬考時**規定自己最多查 5 次**（開 learn.microsoft.com 分割視窗真的查），
練出「這題值不值得查」的判斷。不練這件事，考場上要嘛不敢查、要嘛查到爆時間。

## 5. Definition of Done — 什麼時候可以按下報名

| # | 驗收條件 | 怎麼確認 | 通過 |
|---|---|---|---|
| DoD-0 | **題庫做完**（本專案目前 0 題） | [AZ104-SPEC.md §1](AZ104-SPEC.md) | ☐ |
| DoD-1 | 連續 **2 次**模擬考 ≥ **85%** | 統計視窗 → 歷史成績 | ☐ |
| DoD-2 | **五個領域各自** ≥ **80%** | 統計視窗 → 領域別正確率 | ☐ |
| DoD-3 | 模擬考在 **80 分鐘內**做完（留 20 分鐘 buffer） | 計時器 | ☐ |
| DoD-4 | 錯題本清到 ≤ **20 題**，且每題連續兩次答對 | 分頁 `6` + `QSTAT` | ☐ |
| DoD-5 | 三種特殊題型（`hs`/`dd`/`dl`）**操作**零失誤 | 不是知識錯，是點錯拖錯 | ☐ |
| DoD-6 | **EN 模式**下也能 ≥ 80% | 語言切 `EN` 跑一輪 | ☐ |
| DoD-7 | **官方 Exam Sandbox 跑過至少一次** | <https://aka.ms/examdemo> | ☐ |
| DoD-8 | 官方免費 Practice Assessment 跑過至少一次 | Learn 上的 AZ-104 Practice Assessment | ☐ |
| DoD-9 | 題庫涵蓋 **2026-04-17 版**大綱 §1-2 的每一個功能群組 | 逐格對照 | ☐ |
| DoD-10 | 第 1 節的參數表已對過**當期**官方頁面 | 自己開一次官方頁 | ☐ |
| DoD-11 | **能讀懂 ARM／Bicep 片段**：看得出資源型別、參數、相依 | 找 3 個範本自己讀一次 | ☐ |
| DoD-12 | **NSG 有效規則能手算**：給一組輸入輸出規則，能說出通不通 | 挑 3 題情境題驗證 | ☐ |
| DoD-13 | **查 Learn 的節奏練過**：一次模擬考只查 ≤ 5 題且沒超時 | §4 的 L3 | ☐ |

DoD-11 到 DoD-13 是 AZ-104 專屬的，AZ-900 沒有——
前兩條是這張考試最會拉開分數的兩個實作點，第三條是開書規則帶來的新技能。

## 6. 目前的紅燈與尚未決定的事（backlog）

### 6-1 🔴 EXAM-13：通過門檻的定義與原廠不同

`az104-practice.html` 裡是 `const EXAM_N = 50, EXAM_SEC = 100*60, PASS = 70;`，
`PASS = 70` 目前當成**答對百分比**判定；原廠是 **700/1000 的換算分數**，兩者不等價。
這是從 AZ-900 原封不動繼承的紅燈，**修法也一樣**：要嘛把成績單的用詞從「及格」改成
「答對率」，要嘛在成績單旁註明「原廠是換算分數，這裡只是答對率」。
在 §5 的 DoD-1 把門檻抓到 85% 就是為了吸收這個差距。

### 6-2 ⚪ EXAM-14：多格題的給分方式刻意從嚴

原廠**逐格給分**，本頁**全部格子都對才算這一題答對**。刻意偏離，理由同 AZ-900：
練習時從嚴，考場上只會比預期好。**不修**，但要知道自己的模擬考分數會低估真實分數。

### 6-3 ⚪ EXAM-19：Case study 未支援 —— **需要使用者決定**

AZ-104 可能出現「一組共用情境掛好幾題」的 case study。目前引擎沒有這個題型。
兩條路：

| 做法 | 好處 | 代價 |
|---|---|---|
| **拆成獨立題**（情境複製進每一題的 `q`） | 不用動引擎，馬上能收錄 | 每題都要重讀一次長情境，跟原廠體感不同 |
| **加新的 `k`**（例如 `cs`，一個情境 + 多個子題） | 忠實重現原廠 | 要改 `renderXXX()`、成績單、洗牌、進度續作，工程量不小 |

**遇到第一題 case study 時再決定，不要提前做。**

### 6-4 ⚪ EXAM-20：Lab 不打算做

真的操作 Azure 入口網站不可能在單一 HTML 檔裡模擬。
AZ-104 標示 100 分鐘＝官方分類的「不含 lab」那一檔，風險可接受。
**替代方案**：DoD-11／DoD-12 用「讀範本、手算 NSG」來補這一塊的實作感。

### 6-5 ⚪ EXAM-16：沒跑過官方 sandbox

AZ-900 的第一版把三種題型降級成單選／複選、考完才發現，就是因為沒先跑 sandbox。
**AZ-104 開始收錄題目之前就先跑一次**，特別要看 case study 與 lab 長什麼樣子。

### 6-6 ⚪ EXAM-21：練習頁不做「查 Learn」功能

考中可以開 Learn 是原廠的規則，但練習頁**刻意不內建**這個功能——
自己開瀏覽器分頁查就好，而且那樣才練得到真實的時間成本（§4）。

### 6-7 題庫本身的未完成項

見 [AZ104-SPEC.md §6](AZ104-SPEC.md)。最大的一條是 **DoD-0：一題都還沒有**。
