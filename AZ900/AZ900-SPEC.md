## 4. 工作流程

### 4-1. 把 PDF 頁面轉成圖片

```bash
python tools/render.py <起始頁> <結束頁> [dpi]
# 例：python tools/render.py 19 24 130
```

輸出到 `AZ900/pages/pNNN.png`（路徑已改成相對於本專案，PDF 讀 `AZ900/(new)AZ-900.pdf`；
可用環境變數 `AZ900_PAGES` 覆寫輸出目錄）。
需要 `pip install pymupdf`。130 dpi 足夠辨識，一頁約 200–300 KB；
遇到看不清的小字或紅框，用 PyMuPDF 的 `clip` 參數把該區塊裁切後放大到 260–300 dpi 再讀。

### 4-2. 用 Read 工具「看」圖片並逐題轉錄

一次讀 3–4 頁比較不會爆 context。轉錄時要同時產出：中文題幹、英文題幹、中英選項、中英解析、螢光筆標記、換行。

### 4-3. 把新題目寫成一個 batch 檔

格式見第 5 節。要用 `append.py` 接在陣列尾端時，檔案開頭必須是 `,`；
要插在陣列中間（補跳號題）則開頭不加逗號，見第 14 節。

### 4-4. 附加並灌回 HTML

```bash
python tools/append.py tools/bank_doc.current.js <你的batch檔>
python tools/splice.py tools/bank_doc.current.js
```

- `append.py` 把 batch 接到 `bank_doc.current.js` 陣列尾端
- `splice.py` 用 `bank_doc.current.js` 整段取代 HTML 裡的 `const BANK_DOC = [...]`
- `bank_doc.current.js` 是**唯一真實來源**，永遠先改它再 splice

### 4-5. 驗證（每批都要跑）

```bash
python tools/extract_html.py check.js
node --check check.js               # 語法
node tools/validate.js check.js     # 資料完整性、標記成對、選項無標記
node tools/check_layout.js check.js # 題幹分段
node tools/check_review.js check.js # 成績單四種狀態
rm check.js
```

小技巧：整批灌進去之前，可以先把 batch 檔包成一個假的
`const BANK_MINE = [];` + `const BANK_DOC = [ …batch… ];` 丟給 `validate.js` 單獨驗，
這樣出錯時不必回頭清理 `bank_doc.current.js`。

全部通過才算完成一批。

## 5. `BANK_DOC` 資料格式

每一筆用 `k` 標示題型（沒有 `k` 就是單選／複選）。四種題型的答案 `a` **一律是陣列**，
差別只在陣列裡放什麼、以及跟哪個欄位逐格對應：

| `k` | 題型 | 作答欄位 | `a` 的意義 |
|---|---|---|---|
| （省略）`mc` | 單選／複選 | `o[]` 選項 | 正解的選項索引，可多個 |
| `hs` | HOTSPOT 多句是非 | `s[]` 敘述 | 與 `s` 逐句對應，`1`＝是、`0`＝否 |
| `dd` | DRAG DROP 配對 | `items[]` 可拖曳項目、`tgt[]` 答案區描述 | 與 `tgt` 逐格對應，值是 `items` 的索引 |
| `dl` | HOTSPOT 下拉 | `sent` 挖空的句子、`dd[][]` 每格的選項 | 與 `dd` 逐格對應，值是該格選項的索引 |

```js
// 單選／複選
{n:63, d:2, t:"儲存體備援", tEn:"Storage redundancy",
 q:"中文題幹（可含 
 換行與 ⟦⟧ 螢光筆標記）",
 o:["選項1","選項2","選項3","選項4"], a:[1],
 e:"中文解析",
 en:{q:"English stem", o:["opt1","opt2","opt3","opt4"], e:"English explanation"}}

// HOTSPOT 多句是非：每一句各自選 是／否
{n:394, d:2, k:"hs", t:"存取層", tEn:"Access tiers",
 q:"以下關於⟦存取層⟧的敘述，正確請選「是」，不正確請選「否」。",
 s:["敘述一","敘述二","敘述三"], a:[1,0,1],
 e:"…", en:{q:"…", s:["…","…","…"], e:"…"}}

// DRAG DROP 配對：把 items 拖到 tgt
{n:395, d:2, k:"dd", t:"儲存體服務", tEn:"Storage services",
 q:"請把左邊的項目拖曳到右邊對應的描述上。",
 items:["Azure 佇列儲存體","Azure Blob 儲存體","Azure 磁碟儲存體","Azure 檔案儲存體"],
 tgt:["⟦用於應用程式之間的可靠訊息傳遞⟧","⟦可從 Windows 裝置以網路共用存取⟧","⟦可設定成使用封存存取層⟧"],
 a:[0,3,1],
 e:"…", en:{q:"…", items:[…], tgt:[…], e:"…"}}

// HOTSPOT 下拉：句子用 {0} {1} 標出挖空位置
{n:46, d:1, k:"dl", t:"服務模型", tEn:"Service models",
 q:"請為下列每一項 Azure 服務，選出正確的雲端服務模型。",
 sent:"⟦Azure 虛擬機器⟧屬於{0}。
⟦Azure SQL Database⟧屬於{1}。",
 dd:[["IaaS","PaaS","SaaS"],["IaaS","PaaS","SaaS"]], a:[0,1],
 e:"…", en:{q:"…", sent:"… {0} … {1} …", dd:[[…],[…]], e:"…"}}
```

| 欄位 | 說明 |
|---|---|
| `n` | 原始 PDF 題號 |
| `k` | 題型；省略＝`mc` |
| `fix` | 順序本身就是題意，不要洗。<br>`dd`：答案區的上下順序有意義（縱深防禦由外而內的巢狀分層、備援程度排序），設 `true` 就只洗可拖曳的項目，答案區不洗。<br>`mc`：答案區是入口網站的截圖（側欄、設定清單、刀鋒節點、工具列、服務磁磚），**選項完全不洗**——原廠考試給的就是那個畫面，洗過就跟文件對不起來。**有 `ico` 就一定要設**，`audit.js` 會擋 |
| `mg` | `true` = 這題是由第一版拆開的子題**合併還原**回來的，不是直接從 PDF 轉錄 |
| `ext` | `true` = **這一題不在原始 PDF 裡**，是由外部題庫來源補進來的（見 §2）。與 `mg`／`vf` 互斥——那兩個的語意是「子題合併還原」與「已與原始文件核對」，對這種題目都不成立。題頭顯示紫色徽章，`v0` 裡要寫清楚外部來源與可信度 |
| `vf` | `true` = 已回頭與原始文件逐字核對過 |
| `v0` | 原始文件上的樣子（純文字，含題號／選項欄／答案區與紅框標的正解）。有這個欄位，題頭的徽章就能點開對照 |
| `d` | 領域：`1` 雲端概念 / `2` Azure 架構與服務 / `3` 管理與治理。PDF 沒標，由轉錄者依內容判斷 |
| `t` / `tEn` | 短主題標籤，中英各一，顯示在題目上方 |
| `q` / `e` | 中文題幹、解析 |
| `ico` | 只用在 `mc`：服務圖示，與 `o` **逐項對應**的 data URI 陣列（見 §9-2）。洗牌時會跟著 `o` 一起換位 |
| `en` | 英文版，**逐格的順序必須與中文完全對應**（洗牌時會一起換位） |

**鐵則**
- 中英的 `o` / `s` / `items` / `tgt` / `dd[g]` 長度必須一一相等
- **可以「選」的東西絕不可出現 `⟦⟧` 標記**（`o`／`items`／`dd`）— 標了等於洩答案，`validate.js` 會擋
- `hs` 的 `s[]`、`dd` 的 `tgt[]` 屬於題幹，**可以**標
- `dl` 的 `sent` 裡 `{0}…{n-1}` 必須剛好對上 `dd` 的格數，中英都要
- `e` 與 `en.e` 都不可留空

**計分**：多格題型一律**全部格子都對才算這一題答對**（原廠是逐格給分，這裡從嚴）。

## 6. 題型對應規則

PDF 的題型與練習頁的 `k` 對應如下。**三種原廠題型都已原生支援，不再降級**：

| PDF 題型 | `k` | 練習頁的作答方式 |
|---|---|---|
| 一般單選 | `mc` | 點選一個選項 |
| 複選（Each correct answer presents part of the solution） | `mc` | 點選多個選項，題目上方標示「需選 N 項 · 已選 x」；**要剛好選滿 N 項**才能批改／往下一題，也不吃第 N+1 項（原廠考試就是這樣擋的，2026-07-28 考後回饋） |
| Yes / No 單句 | `mc` | 兩個選項，**不洗順序**，A/B 對得上原文件 |
| HOTSPOT 多句 Yes/No | `hs` | 逐句各自點「是 / 否」，每輪洗敘述順序 |
| DRAG DROP 左右配對 | `dd` | 拖曳（或先點項目再點格子）把項目放進答案區 |
| HOTSPOT 單格下拉 | `dl` | 句子裡一個下拉選單 |
| HOTSPOT 多格下拉 | `dl` | 句子裡多個下拉選單，`sent` 用 `{0}{1}` 標位置 |
| HOTSPOT 服務／刀鋒圖示選擇 | `mc` ＋ `ico` ＋ `fix` | 原題是在入口網站的畫面上點一個，等同單選，維持 `mc`，但**要把圖示一起放上去、而且不洗牌**（見 §9-2）。目前 9 題：#97 #109 #168 #199 #215 #276 #328 #399 #403 |
| DRAG DROP 巢狀分層（#227） | `dd` + `fix` + `nest` | 三個空格插在固定的七層同心方框裡，拖進去；答案區順序不洗 |
| DRAG DROP 排序（#162、#467） | `dd` + `fix` | 把項目拖進答案區排出順序；答案區是有意義的排序，不洗 |

### 洗牌規則

| `k` | 洗什麼 | 為什麼 |
|---|---|---|
| `mc` | 選項順序（只有兩個選項的是非題不洗） | 撰寫時正解都排在第一個，不洗就「一律選 A」全對 |
| `mc` + `fix:true` | **完全不洗** | 答案區是入口網站的截圖，順序是畫面的一部分（9 題有 `ico` 的都是） |
| `hs` | **敘述順序** | 逐句作答，順序不帶答案資訊；洗過就沒辦法把整題背成「YNY」這種樣式 |
| `dd` | 項目順序＋答案區順序 | 兩邊都洗，位置記憶完全失效 |
| `dd` + `fix:true` | 只洗項目順序 | 答案區是有意義的排序（巢狀分層），洗了題目就不成立 |
| `dl` | 每一格各自洗自己的選項清單 | 同上 |

洗牌時**中英文必須同步換位**，`a` 也要跟著重新對應；`tools/validate.js` 與瀏覽器測試都會驗。

### 拆題與合併的歷史

## 7. 中文翻譯風格

第一批做出來被打回過，原因是照英文語序直譯、機翻腔太重。**定案的寫法**：

| 不要這樣 | 要這樣 |
|---|---|
| 注意：本題屬於一系列設定相同、但結果各異的題目。請判斷該解決方案是否符合需求。 | 注意：本題與另外數題的情境完全相同，但每一題提出的解法不同，請個別判斷。 |
| 解決方案：你應該使用 X。 | 解法：使用 X。 |
| 此解決方案是否符合目標？ | 這個解法是否達成目標？ |
| 使用盡可能少的虛擬機器與可用性區域 | 用到的虛擬機器與可用性區域數量要越少越好 |
| 貴公司 / 你獲知 / 你的任務是 | 你的公司 / 你得知 / 你要 |

原則：**照意思翻，不照語序翻**；`as ... as possible` 用「越…越好」；被動語態改主動；長句斷成短句。

英文題幹則**完全照 PDF 原文**，不要改寫。

## 8. 解析風格（重點）

使用者明確要求：**解析要詳細，而且要把整組可比較的選項一次列出來**。

### 8-1. 整組列出

只要題目牽涉到「等級／層級／角色／方案／備援選項」，就把**整組都列出來**，而不是只解釋正確答案。例如：

- 支援方案題 → Basic / Developer / Standard / Professional Direct / Premier 五級全列
- 儲存體備援題 → LRS / ZRS / GRS / RA-GRS / GZRS / RA-GZRS 六種全列
- App Service 題 → Free / Shared / Basic / Standard / Premium 五層的儲存上限與執行個體數
- SLA 題 → 無 SLA → 99.9% → 99.95% → 99.99% 四個級距的條件
- 權限題 → 擁有者 / 參與者 / 讀取者 / 使用者存取系統管理員
- 服務模型題 → IaaS / PaaS / SaaS 各自的責任分界

### 8-2. 排版

用 `\n` 換行、`・` 開頭條列。`.expl` 有 `white-space: pre-line`，成績單用 `escHl()` 把 `\n` 轉成 `<br>`。

### 8-3. 標出可疑答案

PDF 的紅框是標註者的判斷，**已知有錯或有爭議**。遇到時照抄紅框答案（使用者要求忠實轉錄），但**在解析裡說清楚**。目前已標出的爭議：

| 題號 | 問題 |
|---|---|
| #1 | 框了 Basic 卻沒框 Premier。Basic 只能開帳單類支援要求，Premier/Unified 也能開；沒框多半因為拖放答案區只有四格 |
| #34 | 「PaaS 提供專業開發服務持續加入功能」標為 Yes，敘述含糊 |
| #43 | 「App Service + 儲存體帳戶」標 No、旁註 IAAS，但**儲存體帳戶其實是 PaaS**；比較站得住腳的理由是缺少資料庫層 |
| #68 | Cosmos DB 問「哪種 offering」，選項同時有 PaaS 與 serverless。標準答案 PaaS（serverless 是計費形態不是服務模型），但 serverless 是強力干擾項 |
| #75 | 「Azure Files 是 IaaS」標為 Yes，與 #43 把儲存體當 IaaS 來否定答案的邏輯自相矛盾。建議記 Microsoft 教材說法：儲存體歸 IaaS 這類基礎資源 |
| #394 | 「封存層可以在帳戶層級設定」標為 Yes，但封存層**只能設在個別 Blob 上**，帳戶預設層只有熱／冷／冷卻三種。正解應為 No |
| #403 | 「為訂用帳戶建立新使用者」框了 **Subscriptions**，但使用者是 Entra ID 的身分物件，正解應為 **Azure Active Directory**。訂用帳戶刀鋒底下的 IAM 做的是「指派角色給既有使用者」，不是「建立使用者」 |
| #407 | 「追蹤 Azure 資源的成本」框了 **usage and quotas**（那是容量配額，不是金額），多數社群答 **tags**；`budgets` 也是強力干擾項 |

寫法：先照標記給答案，再用「注意：…這個標記在社群有爭議」或「提醒：…」說明。

### 8-5. 配對題解析的格式（已定案）

配對題與多格下拉的解析一律寫成**「共用對照一次 + 逐格重點」**：

```
（開頭一段：把整組可比較的項目一次列全，照 §8-1 的要求）
（再一行判斷訣竅／記法）

【答案區的描述】→ 正解項目
（只寫這一格獨有的重點：關鍵字在哪、為什麼不是另一個）

【下一格的描述】→ 正解項目
（同上）
```

英文版用 `[description] -> item`。

**鐵則：`【…】` 裡的字必須與 `tgt` 去掉 `⟦⟧` 之後逐字相等**，英文 `[…]` 與 `en.tgt` 亦同。
改 `tgt` 就要同步改小標，否則成績單與解析對不起來。

這個格式是為了解決舊版的問題：每個子題原本都是獨立題目，都照 §8-1 「整組列出」寫過一次，
合併後同一組對照會重複 N 次（實測 102 段裡有 80 段重複，約佔配對題解析總量的 53%）。
2026-07-28 全部改寫完畢，中文解析平均長度由 678 字降到 614 字，最長由 2939 降到 2624。

- PDF **沒有任何解析文字**（只有題目、Answer Options 欄、Answer Area 描述、紅框標答案），
  已抽查第 16 頁 #54 與 115–138 頁確認。所以解析內容要靠 Azure 知識寫，PDF 只能核對題目本身。
- 核對 PDF 的另一個價值見 §15：可拖曳項目被交集法弄丟、下拉選項順序被搬動、
  描述被加上多餘前綴，這幾類偏差都是這一趟核對才抓出來的。

## 9-1. 螢光筆標記

- 用 `⟦…⟧` 包住要標記的片段，渲染成黃色螢光筆（`mark.hl`）
- **只標題幹**，對應 PDF 紅框圈住的關鍵條件（決勝條件、Solution 那一句）
- **絕對不標可以選的東西** — `o`（選項）／`items`（可拖曳項目）／`dd`（下拉選項）
  一律不標；PDF 會圈正確選項，但練習工具標了就是洩題
- **可以標**：`hs` 的敘述 `s[]`、`dd` 答案區的描述 `tgt[]`、`dl` 挖空的句子 `sent`，
  這些都屬於題幹
- 解析裡也可以用，會以較淡的螢光呈現
- 標記必須成對，`validate.js` 會檢查

## 9-1b. 輕量 markdown

`q`／`e` 這些欄位是純文字，但解析常常需要強調或貼程式碼。引擎的 `mdHtml()` 支援四種標記，其餘一律當字面：

- `⟦螢光筆⟧` → `<mark class="hl">`（見上）
- `**粗體**` → `<b>`
- `` `行內程式碼` `` → `<code>`
- ```` ```\n區塊\n``` ```` → `<pre class="code">`（保留縮排；容器是 `white-space:pre-line`，只有 `<pre>` 才不會把連續空白壓成一個）

標記必須成對，落單會直接字面顯示（例如少寫一個 `**`）。挖 ``` ``` ``` 區塊用的佔位符是
`\u0000` 轉義，不能用「空白＋數字＋空白」這種寫得出來的字樣，否則解析裡任何一個數字
都會被誤當成區塊塞回去。

## 9-2. 服務圖示（`ico`）

有幾題的答案區在原題裡是**入口網站的服務清單或磁磚**，每一格都是「圖示＋名稱」。
只放文字會失真，所以加了選配欄位 `ico`：與 `o` 逐項對應的 data URI 陣列。

```js
{n:399, d:2, mg:true, vf:true, t:"…",
 o:["Azure Cosmos DB","虛擬機器（Virtual machines）", …],
 a:[3],
 ico:["data:image/svg+xml;base64,…","data:image/png;base64,…", …],   // 與 o 逐項對應
 …}
```

**鐵則**
- `ico` 長度必須等於 `o`，而且**只能用在 `mc`**（`audit.js` 會擋）
- 一律內嵌成 data URI，**不可連外**（§13-7 檔案要單一自足）
- **有 `ico` 就一定要有 `fix:true`**。答案區是入口網站的截圖，側欄／清單／工具列的
  順序是畫面的一部分，洗過就跟文件對不起來了。`audit.js` 會擋，`test_shuffle.js`
  會驗 200 輪之後順序一格都沒動
- 選項順序一律**照原文件**。轉錄時很容易順手把正解排到第一個——`#97 #168 #276 #328
  #399 #403` 全都中過這個招，已逐題改回。改順序記得同步改 `a`

### 圖示要用哪個來源

兩個來源，判斷規則如下（**逐格判斷，同一題可以混用**）：

| 狀況 | 用哪個 | 工具 |
|---|---|---|
| 原始截圖裡的圖示完好 | **裁 PDF**，最忠實 | `tools/icons_pdf.py` |
| 圖示被截斷，或被紅色標註框蓋住 | 官方圖示包的 SVG | 同上，框改寫成 `("名稱","pack:相對路徑")` |
| 那個圖根本不是服務圖示（例如入口網站的「＋ 建立資源」） | 只能裁 PDF | `tools/icons_pdf.py` |

官方包是 `Azure_Public_Service_Icons_V24/`（附 `Microsoft_Terms_of_Use.pdf`，
授權允許用於架構圖、訓練教材與文件）。**包裡沒有的東西不少**——實際遇到過缺
`Azure Active Directory`、`Create a resource`、`Azure Data Box Gateway`、`Azure Stack Edge`。

實際的四題各自怎麼決定：

| 題 | 來源 | 為什麼 |
|---|---|---|
| #97 | 6 個裁 PDF ＋ 1 個官方包 | 紅色標註框**畫在 `Local network gateways` 的圖示上面**，下緣被蓋掉裁不回來 |
| #109 | 4 個全裁 PDF | 卡片圖示全部完好 |
| #399 | 5 個全用官方包 | `Azure Cosmos DB` 那列上緣被原始截圖切掉，只換一個會變成新舊圖示混搭 |
| #403 | 7 個全裁 PDF | 磁磚全部完好，而且官方包裡沒有 `Azure Active Directory` 與 `Create a resource` |

### 裁圖的兩個坑

1. **紅色標註框緊貼圖示。** 框太寬會把紅線裁進來，框太窄會把圖示邊緣切掉。
   `icons_pdf.py` 會印出去白邊後的**實際內容邊界**（換算回 130dpi 座標），照著調就好，
   不要用眼睛量。真的閃不開時就換官方包。
2. **來源截圖本身解析度就低**，用 300dpi 裁只是把雜訊放大、檔案大三倍。
   `JOBS` 可以逐題指定 dpi，p29／p33 那種低解析度的頁用 200 就夠
   （UI 上只顯示 26px）。

`tools/clip.py` 是量座標用的：把 PDF 的任一塊放大存成圖，座標用的是
`render.py` 產出的那張 130dpi PNG 上的像素，量起來直覺。

## 10. 題幹換行

題幹用 `\n` 分段，渲染時每段一個 `<p>`：

- 第一段若以 `注意：` / `Note:` / `（原題` / `（原始` / `(The ` / `DRAG DROP` 開頭 → 套用 `.qnote`（小字、灰、下方虛線），與真正的題目分開
- 其餘各段 → `.qtext`（粗體）
- **`解法：` / `Solution:` 之前要斷行**，讓提出的解法自成一段（對應 PDF 的排版）

範例：

```
注意：本題與另外數題的情境完全相同，但每一題提出的解法不同，請個別判斷。\n
你的公司底下有多個業務單位……你要制定一套能自動建立 Azure 資源的策略。\n
⟦解法：把 Azure Resource Manager 範本納入策略⟧。這個解法是否達成目標？
```

| 統計視窗 | `openStat()`、`domainStats()`、`stampOf()` | 領域別正確率、弱點題清單 |
| 作答總覽 | `openOverview()`、`closeOverview()`、`ovwrap` | 仿原廠 Review screen：交卷前先看哪些沒作答、哪些標了待複習 |
| 待複習標記 / 備註 | `S.flags[]`、`S.notes[]` | 模擬考中逐題標記與備註 |
| 跳題 | `jumpTo()`、`jumpRange()`、`paintJump()`、`sayJump()` | 直接跳到某一題 |
| 進度續作 | `SESS`、`sessToJSON()`／`sessFromJSON()`、`persistSess()`、`restoreSessions()`、`sigOf()` | 關掉瀏覽器再回來能接著作答；**洗牌順序也要存**，見下方 |
| 匯出／匯入 | `exportSave()`、`importSave()` | 把進度與紀錄搬到別台機器 |
| 模擬考往下一題的關卡 | `examGate()` | 複選題沒選滿「需選 N 項」就擋住「下一題」與 →，仿原廠考試；上一題／總覽／交卷不受限 |
| 複選「需選 N 項」 | `mcNeed()`、`mcShort()`、`ansDone()`、`paintMulti()`、`bumpMulti()`、`nagMulti()` | 徽章即時顯示已選幾項；選滿轉綠、不吃第 N+1 項；沒選滿不能批改／不能往下一題；只選一半在總覽與「已作答」計數都算未作答 |

**`permuteOptions(q, p)` 多了第二個參數**：帶進先前的洗牌結果就會洗回一模一樣的順序，
洗完把用到的順序記在 `q._p`。進度續作存的就是這個——否則「你選的是第幾個選項」對不回同一個選項。

### 兩個踩過的坑（改介面時注意）

1. **`paintHl()` 寫入的容器不可以是 flex 容器。** 它會把文字拆成「文字節點 + `<mark>`」

   | 沒有來源，**且來源之間互相矛盾** | 先確認矛盾是真的（見上面 #380 的教訓），真的矛盾才維持現狀，不要編造 | 目前無 |

   「只有一個來源」不算數；「來源彼此打架」更不算數。
