# AZ-900 原廠考試方式 × 練習方式 — TDD 規格

這份文件用測試驅動開發（TDD）的寫法，把兩件事變成**可以逐條驗收的測項**：

1. **原廠考試怎麼考** → 練習頁 `az900-practice.html` 是否忠實重現（機器可測）
2. **要怎麼練才會過** → 你本人是否達到報名的門檻（自己可測）

與 [AZ900-SPEC.md](AZ900-SPEC.md) 的分工：SPEC 講**題庫怎麼做**（資料格式、轉錄流程），
本文件講**考試怎麼考、練到什麼程度才算完成**。兩份都要看。

第 1 節的規格全部在 **2026-07-28 查證過官方頁面**，來源列在第 10 節。

## 0. TDD 在這裡是什麼意思

一般 TDD 的循環是「先寫會失敗的測試 → 寫最少的程式讓它變綠 → 重構」。搬到考照上：

| 階段 | 軟體開發 | 這個專案 | 讀書 |
|---|---|---|---|
| 🔴 **紅** | 寫一個會失敗的測試 | 把原廠的行為寫成測項，跑 `uitest.py` 看它 FAIL | **先考再讀**：直接做一輪題，把錯的挑出來 |
| 🟢 **綠** | 寫最少的程式讓它通過 | 改 `az900-practice.html` 直到 PASS | 只補「這一題錯在哪」的那個知識點，不整章重讀 |
| ♻️ **重構** | 不改行為，改結構 | 抽共用函式、清重複解析 | 把散的知識點併成**整組對照表**（SPEC §8-1），下次一次記住一整組 |

**兩個受測物件（SUT）**

| 代號 | 受測物件 | 誰來測 | 通過標準 |
|---|---|---|---|
| **SUT-A** | 練習頁 = 原廠考試的模擬器 | `uitest.py` / `validate.js` 等腳本 | 第 2 節的 `EXAM-xx` 全綠 |
| **SUT-B** | 你自己 | 練習頁的模擬考與統計 | 第 5 節的 Definition of Done |

**黃金標準（test oracle）＝ 官方 Exam Sandbox**

微軟提供 **<https://aka.ms/examdemo>**：不用錢、不用報名，直接體驗**真正的考試介面**——
同樣的開場說明、保密協議、左側導覽、計時器、標記待複習、Review screen，
以及各種題型（多選、拖放、Hot area、Build list、Active screen）的實際操作方式。

這是本專案唯一能拿來對照的權威來源。**任何 `EXAM-xx` 測項有爭議，以 sandbox 的實際行為為準，
不是以記憶為準。** 第一版之所以把三種題型降級成單選／複選、考完才發現，就是因為沒先跑 sandbox。

**標記法**（全文通用）

- 狀態：🟢 已通過 ／ 🔴 已知不通過 ／ ⚪ 尚未實作或尚未驗證
- 來源：`[官]` 2026-07-28 查證官方頁面 ／ `[親]` 考後親身回饋 ／ `[社]` 社群回報 ／ `[待確]` 尚未證實

官方**刻意不預告**題型，但 sandbox 可以實際玩到這些：多選、拖放、Hot area、Build list、Active screen、Mark review、Review screen。對應到本專案：

| 原廠題型 | 本專案 `k` | 作答方式 |
|---|---|---|

| 複選（Each correct answer presents part of the solution） | `mc` | **要剛好選滿 N 項** |

### 1-4 作答介面的硬規則 `[親]`

2026-07-28 考後回饋的重點，也是練習頁第一版**做錯過**的地方：

1. **複選題選滿 N 項才能往下一題**——沒選滿會被擋住，選滿之後**不吃第 N+1 項**，
   想改要先取消一項。不是靠提示，是直接擋。
2. **拖放就是真的拖放**，不會降級成單選；下拉就是下拉；多句是非要逐句點。
   任何把題型降級的模擬，都會讓你在考場上**第一次見到那個介面**。
3. 可以 **Mark for review** 並在 **Review screen** 一次看完哪些沒作答、哪些標了。
4. **可以自由回頭改答案**（Fundamentals 沒有 case study，不存在不可回頭的段落）——
   但**休息除外**，見下一條。
5. 不倒扣，**交卷前不能留白**。

### 1-5 休息時間的陷阱 `[官]`

Fundamentals 也可以中途休息，但規則很坑：

- 45 分鐘裡**已經內含 5 分鐘的休息額度**（微軟為此拿掉了一些題目）。
- **考試時鐘不會停。** 休息多久都算你的作答時間。
- **休息之後不能回到休息前看過的任何題目**——即使沒作答、即使標了待複習。
- problem-solution 題組（Solution: … 那種）**中途不能休息**，只能在題組前後休息。

→ 結論：**AZ-900 只有 45 分鐘，不要休息。** 進去就一路做完。

### 1-6 考試當天的流程

```
報到（雙證件 / OnVUE 環境檢查）
  → 保密協議 NDA + 開場說明（座位時間 65 分鐘的前置，不吃作答的 45 分鐘）
  → 作答 45 分鐘（左側導覽有計時器、剩餘題數、Mark review、休息鈕）
  → Review screen：掃一次「未作答 / 已標記」
  → 交卷 → 意見回饋 → 數分鐘內出分（Pass/Fail + 各領域長條圖）
  → 24 小時內 Learn 個人檔案出現徽章與證書
```

### 1-7 常見誤解

| 誤解 | 事實 `[官]` |
|---|---|
| 答對 70% 就過 | 是 **700/1000 換算分數**，官方明講「可能不等於 70% 的分數」。題目難 → 需要的分數較低；題目簡單 → 需要的分數較高 |
| 可以開 Microsoft Learn 查 | Fundamentals **不能**，那是 role-based 考試的待遇 |
| 不確定就留白比較安全 | **不倒扣**，留白 100% 拿不到分 |
| 多格題答錯一格整題就沒分 | 原廠**逐格給分**（本練習頁刻意從嚴，見 §7-2） |
| 成績單長條圖能算出答對幾題 | 官方明說**不能**；各領域題數不同，長條圖只看得出強弱 |
| 遇到超綱怪題 = 準備不足 | 可能是**不計分的試驗題**，官方確認卷中有 |
| 可以問哪幾題錯了 | 官方**不提供**，只有領域長條圖 |
| 認證要每年續 | Fundamentals **不過期** |

## 3. SUT-B：練習方式的 TDD 循環

### 3-1 核心原則：先考，再讀

最常見的錯誤讀法是「把教材／題庫從頭讀一遍，最後才做題」。用 TDD 的語言講，
那是**先寫實作再補測試**——你不知道自己哪裡不會，讀的時間全花在已經會的東西上，
而且沒有任何一個時點能證明「我到底行不行」。

**正確的循環（每一輪 25–40 分鐘）**

```
🔴 紅：直接開一輪題（分頁 0 或某個領域），不查資料，不會就猜
        └ 產出：這一輪的錯題 → 自動進「錯題本」分頁

🟢 綠：只針對錯的那幾題，讀解析、補那一個知識點
        └ 停止條件：能用自己的話說出「為什麼是它、為什麼不是另外三個」
        └ 不要順便讀旁邊的章節，那是超出測試範圍的實作

♻️ 重構：把剛補的點併進一張「整組對照表」
        └ 例：錯了 GRS 的題，就把 LRS/ZRS/GRS/RA-GRS/GZRS/RA-GZRS 六種一次列出來
        └ 這一步就是 SPEC §8-1 的「整組列出」，解析已經幫你寫好了，抄進自己的筆記
        └ 隔天要**重跑一次錯題本**，確認沒把別的知識點改壞（回歸測試）
```

### 3-2 五種錯，修法完全不同（Defect Triage）

答錯之後**先分類再修**，分錯類就會用錯方法：

| 類別 | 症狀 | 修法 | 不要做 |
|---|---|---|---|
| **知識缺口** | 根本沒聽過這個服務 | 讀解析的整組對照，加進筆記 | 只背這一題的答案 |
| **讀題錯** | 知識會，但看漏「最少成本」「不得停機」這種決勝條件 | 練習頁的 `⟦螢光筆⟧` 就是圈這個。養成**先找螢光筆**再看選項 | 怪自己粗心就過去了 |
| **題型操作失誤** | 知識會，但拖錯格、複選只選一項 | 專練該題型（`hs`／`dd`／`dl`），練到不用想 | 用單選介面練，那練不到 |
| **記憶衰退** | 一週前會，現在不會 | 進錯題本，**間隔重複**：1 天 / 3 天 / 7 天各一次 | 一次讀十遍 |
| **題目本身有爭議** | 你的答案有理，標記答案也有理 | 記標準答案去考試，但兩邊理由都要知道 | 為了它懷疑整套知識 |

> 最後一類真實存在：SPEC §8-3 已列出 **8 題**已知有爭議
> （#1、#34、#43、#68、#75、#394、#403、#407），**不列入你的正確率**。
> 這對應官方的另一件事：卷中本來就有**不計分的試驗題**，遇到怪題不要動搖。

### 3-3 三個領域的配分與時間分配

| 領域 | 分頁 | 官方權重 | 建議時間 | 特性 |
|---|---|---|---|---|
| 雲端概念 | `1` | 25–30% | 20% | 觀念題，讀懂就穩：CapEx/OpEx、共同責任模型、IaaS/PaaS/SaaS、serverless |
| Azure 架構與服務 | `2` | **35–40%** | **45%** | 題量最大、服務名最多，最容易失分；2026-07-20 的 compute/networking 有微調 |
| 管理與治理 | `3` | 30–35% | 35% | 成本管理、Policy／資源鎖／Purview、Arc、IaC、Monitor 三兄弟；名字很像最容易混 |

## 4. 測試金字塔：四層練習，各有頻率與門檻

| 層 | 對應 | 怎麼跑 | 頻率 | 通過門檻 |
|---|---|---|---|---|
| **L1 單元** | 單一知識點 | 分頁 `1`–`3` 挑一個領域小量作答 | 每天 | 當下能講出為什麼 |
| **L2 整合** | 一個領域整體 | 分頁 `1`／`2`／`3` 各跑完整一輪 | 每 2–3 天 | 該領域 ≥ 80% |
| **L3 端對端** | 整場考試 | **模擬考模式**：40 題 / 45 分鐘 / 不看解析 / 不中斷 | 每週 1–2 次 | ≥ 85%，且 35 分鐘內做完 |
| **L4 回歸** | 修好的不能再壞 | 分頁 `4` 錯題本 + 分頁 `5` 星號題 | 每次 L2/L3 之後 | 同一題**連續兩次答對**才算修好 |

**L3 一定要計時、一定要用模擬考模式跑。** 練習模式每題批改會給你回饋，考場上不會；
45 分鐘 40 題等於**每題平均 67 秒**（而且那 45 分鐘裡還含 5 分鐘休息額度），
配對題與多格下拉會吃掉遠超過一分鐘，時間感只能靠 L3 練出來。

**回歸測試的紀律**：錯題本裡的題目答對**一次不算修好**——很可能只是還記得剛才看過的答案。
`QSTAT` 有記每題的答對／答錯／看答案次數（統計視窗 → 弱點題），用那個判斷。

## 5. Definition of Done — 什麼時候可以按下報名

以下**全部**綠燈才算完成。任何一條紅燈就回到第 3 節的循環，不要賭。

| # | 驗收條件 | 怎麼確認 | 通過 |
|---|---|---|---|
| DoD-1 | 連續 **2 次**模擬考 ≥ **85%** | 統計視窗 → 歷史成績 | ☐ |
| DoD-2 | 三個領域**各自** ≥ **80%** | 統計視窗 → 領域別正確率 | ☐ |
| DoD-3 | 模擬考在 **35 分鐘內**做完（留 10 分鐘 buffer） | 計時器 | ☐ |
| DoD-4 | 錯題本清到 ≤ **20 題**，且每題連續兩次答對 | 分頁 `4` + `QSTAT` | ☐ |
| DoD-5 | 三種特殊題型（`hs`/`dd`/`dl`）**操作**零失誤 | 不是知識錯，是點錯拖錯 | ☐ |
| DoD-6 | **EN 模式**下也能 ≥ 80% | 語言切 `EN` 跑一輪 | ☐ |
| DoD-7 | **官方 Exam Sandbox 跑過至少一次** | <https://aka.ms/examdemo> | ☐ |
| DoD-8 | 官方免費 Practice Assessment 跑過至少一次 | Learn 上的 AZ-900 Practice Assessment | ☐ |
| DoD-9 | 題庫涵蓋 **2026-07-20 版**大綱的每一個 bullet | 見 §7-5 | ☐ |
| DoD-10 | 第 1 節的參數表已對過**當期**官方頁面 | 自己開一次官方頁 | ☐ |

**DoD-1 為什麼訂 85% 而不是 70%**：原廠 700 分是換算分數，不等於答對率；
社群普遍的經驗值是**穩定答對 75–80% 以上**才安全。本題庫是考古題、且刻意從嚴計分，
所以再往上抓一點到 85%。

**DoD-6 為什麼重要**：中文是翻譯版，偶爾會出現看不懂的句子，考場上可以看英文原文。
而且官方明講**中文版比英文版晚約 8 週更新**——遇到新題時中文可能更彆扭。
本頁的三段語言模式（中／中+EN／EN）就是為了練這件事：
平常用「中+EN」熟悉術語英文，考前一週至少跑一輪純 `EN`。

**DoD-7 是最便宜的一條**：不用錢、不用報名、10 分鐘跑完，卻是唯一能事先看到真實介面的方法。
第一版把題型降級成單選／複選就是漏了這一步。**沒跑過 sandbox 不要進考場。**

**DoD-4 的門檻不是 0**：有 8 題本身有爭議（§3-2），清不掉是正常的。

## 7. 目前的紅燈（backlog）

### 7-1 🔴 EXAM-13：通過門檻的定義與原廠不同

`az900-practice.html:6295` 是 `const EXAM_N = 40, EXAM_SEC = 45*60, PASS = 70;`，
`PASS = 70` 目前當成**答對百分比**判定。原廠是 **700/1000 的換算分數**，
官方明講「可能不等於 70% 的分數」，且**題目越簡單、需要的分數越高**。

- 影響：練習頁顯示 72%「通過」，不保證原廠會過。
- 處理方向（擇一）：
  1. **最省事**：不改程式，在成績單旁加一行「本頁是答對率，原廠是換算分數，安全線抓 85%」。
  2. 把 `PASS` 提高到 85，與 DoD-1 一致。
- **不要**去猜換算公式：官方不公布，硬做只會做出另一個假的數字。

### 7-2 ⚪ EXAM-14：多格題的給分方式刻意從嚴

官方原文是「每答對一個部分得一分，可以得到全部、部分或零分」，也就是**逐格給分**；
本頁 `hs`／`dd`／`dl` 一律**全部格子都對才算對**（SPEC §5）。

這是**刻意的偏離**，不是缺陷：練習從嚴，考場才有餘裕。**不要改回逐格給分**，
否則 DoD-1 的 85% 會被灌水。要改的話只能在成績單「額外」顯示一個逐格分數當參考。

## 9. 這份文件自己的維護規則

1. **考完一定要回來改。** §6 的「考後補填欄」與所有 `[待確]` 要更新成 `[親]`。
2. **官方頁面改了就改這裡。** 每次報名前重跑 DoD-10；大綱更新（`Skills measured as of …` 那一行的日期）要重跑 DoD-9。

   單選／複選、直到考完才發現的原因。
